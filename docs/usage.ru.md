# REAL 0.3 — что изменилось и как этим пользоваться

Короткая инструкция по новой версии форка. План работ и разбор исходного кода —
в [plan-usage-improvements-ru.md](plan-usage-improvements-ru.md), справочник по всем
настройкам — в [CONFIG.md](CONFIG.md).

---

## 1. Что сделано по пунктам

### 1.1. Сворачивание в трей
- «Свернуть» уводит окно в трей (`application.minimizeToTray`).
- Крестик окна по умолчанию **завершает программу** (`application.closeButtonAction:
  "exit"`, в окне настроек — «Кнопка закрытия: Завершить программу»); со значением
  `minimize` («Свернуть в трей») крестик тоже прячет окно в трей.
- У значка в трее теперь есть **меню** (правый клик) и подсказка со статусом;
  левый клик — показать/спрятать окно, один клик срабатывает надёжно.
- Значок восстанавливается после перезапуска `explorer.exe` (обрабатывается
  `TaskbarCreated`).
- Старт сразу в трее: `--tray` или `application.startMinimizedToTray: true`.
- Без значка в трее (флажок «Показывать значок в трее» снят) окну некуда прятаться:
  «Свернуть» сворачивает его на панель задач, крестик завершает программу, а при
  запуске окно видно сразу. В окне настроек эти три настройки тогда серые.

### 1.2. Какие устройства обрабатываются
- В Windows у каждого устройства есть **два «по умолчанию»**: обычное устройство по
  умолчанию и устройство связи по умолчанию («Параметры → Система → Звук»).
- REAL берёт **все** устройства по умолчанию выбранного направления (`audio.dataFlow`:
  вывод, запись или оба) и держит малый буфер на каждом — и на обычном, и на
  устройстве связи. Совпадающие устройства обрабатываются один раз.

### 1.3. Перезапуск аудиопотоков
- Вручную: **меню трея → «Перезапустить»**, **«REAL → Перезапустить»** в строке меню
  окна, маленькая кнопка с круглой стрелкой в правом конце строки состояния,
  командная строка `REAL.exe --reinit`
  (вторая копия не запускается, а передаёт команду уже работающей). Перезапускаются
  аудиопотоки — они создаются заново, сама программа продолжает работать.
- Если перед этим снижение задержки было выключено (галочка «REAL запущен» снята),
  «Перезапустить» **включает его снова** и применяет — то есть команда всегда
  приводит к видимому результату.
- Автоматически (блок «Автоматический перезапуск» в окне настроек, `audio.reinit`):
  - смена устройства по умолчанию — любого из двух: обычного или устройства
    связи («Параметры → Система → Звук»);
  - подключение и отключение устройства (переход в активное или неактивное
    состояние);
  - появление нового устройства и удаление устройства (оба выключены по умолчанию:
    повторное подключение знакомого устройства Windows присылает как подключение —
    пункт выше);
  - выход из сна / Modern Standby;
  - разблокировка сеанса;
  - плюс проверка каждые 30 секунд: жив ли поток и то ли это устройство —
    на случай, если уведомление не пришло.
- При смене устройства снижение задержки включается само, даже если оно было
  выключено — вручную или после того, как устройство перестало отвечать.
- Если устройства по умолчанию нет совсем (например, при старте вместе с Windows
  звук ещё не готов), в журнале — предупреждение «Аудиоустройство по умолчанию не
  подключено.»: это не ошибка программы, а то, что мешает ей работать. Как только
  устройство появится, снижение задержки применится само.
- Если устройство не отвечает (выключено, служба звука перезапускается), попытки
  повторяются с растущей паузой, а уведомление показывается **один раз** — на
  начало сбоя. Через `audio.reinit.failureTimeoutMs` (60 секунд по умолчанию)
  приложение прекращает опрос и выключает снижение задержки; событие об устройстве
  снова включает его. Строка состояния в этом случае: «отключено: аудиоустройство не
  отвечает».
- Всё это происходит **в том же процессе**, без перезапуска программы.
- Уведомления у значка показываются, только когда окно скрыто в трее или свёрнуто:
  пока окно открыто, то же самое видно в его журнале. Уведомление о включении и
  выключении приходит на действия пользователя (меню, `--enable`/`--disable`,
  «Перезапустить»), а не на запуск программы и не на автоматические перезапуски;
  после сна и разблокировки нет и уведомления о смене устройства.
- Копия программы всегда одна (мьютекс `Local\REAL.SingleInstance`): повторный
  запуск передаёт команду работающей копии и завершается, не трогая ни файл
  настроек, ни журнал. Если работающая копия не отвечает, новая тоже не
  запускается и сообщает «REAL уже запущен, но не отвечает».

### 1.4. Обновления больше не навязываются
- По умолчанию (`updates.checkOnStartup: true`) — **одна** проверка при запуске
  программы. Больше запросов за сессию нет, во время работы обновления не
  проверяются. Репозиторий релизов вшит в сборку (`Mutaracha/REAL`) и настройкой не
  меняется.
- `updates.checkOnStartup: false` (снять «Проверять при запуске» на вкладке «Прочее»)
  — **ни одного сетевого запроса** за всё время работы.
- Проверка — один запрос к странице `github.com/Mutaracha/REAL/releases/latest`:
  GitHub перенаправляет его на страницу последнего релиза, и версия берётся из её
  адреса. Лимита API (60 запросов в час на один адрес) у этого способа нет, поэтому
  VPN или общий IP не приводят к отказу «HTTP 403». Пока релизов нет, в журнале
  строка «Опубликованных версий пока нет.» — без уведомления, это не ошибка.
- Найденная версия только показывается уведомлением (клик открывает страницу
  релиза). Скачивания, установки и принудительного закрытия нет.
- Из старого апдейтера осталось только удаление файла `REAL.exe~DELETE`, который
  могли оставить прежние версии.

### 1.5. Внешний файл настроек
- Файл `real.settings.json` лежит **рядом с `REAL.exe`** и создаётся при первом
  запуске со всеми значениями по умолчанию.
- Формат JSON, **комментарии `//` и `/* */` разрешены**, кодировка UTF-8 (BOM тоже
  принимается). Неизвестные ключи не ломают запуск — пишется предупреждение в лог.
- Неподходящее значение в файле (не того типа, вне диапазона, неизвестное слово) не
  применяется: берётся последнее используемое — при запуске значение по умолчанию,
  при «Перечитать» в окне настроек действующее. Предупреждение называет ключ, причину
  и значение, которое используется. Файл больше 1 МБ не читается совсем.
- Приоритет: командная строка → файл → встроенные значения.
- `--config <путь>` — другой файл, `--no-config` — игнорировать файл.
- Правка параметров — в **окне «Настройки REAL»**: пункт **«Опции → Настройки»**
  строки меню окна программы или **«Настройки»** в меню значка. Окно пишет тот же
  `real.settings.json`, поэтому файл остаётся источником истины: что сохранили в
  окне, то и лежит в файле с комментариями. Значения применяются сразу после
  «Сохранить», перезапускать программу не нужно.
- Окно настроек выглядит как обычный диалог Windows: настройки собраны в группы в
  рамках с подписью, у каждой группы своя колонка подписей (с двоеточием после
  подписи). Ширина окна подстраивается под самую широкую строку, высота — под самую
  высокую вкладку. Если задержать указатель на настройке или её подписи, всплывает
  короткое описание — и у серой настройки тоже.
- Внизу окна настроек две кнопки одного размера: **«Отмена»** (ничего не менять) и
  **«Сохранить»** (записать и применить). Сам файл — на вкладке «Прочее», в группе
  «Файл настроек»: путь к нему, **«Открыть»** (тот же файл в редакторе, ручная
  правка по-прежнему возможна) и **«Перечитать»** (заново прочитать файл в окно,
  чтобы поправленное в редакторе значение попало в окно без закрытия). Щелчок по
  пути копирует в буфер обмена путь к папке с файлом, без имени файла.
- С клавиатуры окно настроек открывается с фокусом на вкладках; **Tab** идёт по полям
  открытой вкладки, затем по кнопкам, **Ctrl+Tab** / **Ctrl+Shift+Tab** (и
  **Ctrl+PgDn** / **Ctrl+PgUp**) переключают вкладки. Уровни журнала в списке идут от
  «Выключен (off)» до «Всё (trace)».
- Поля окна настроек проверяются, когда из них уходит фокус: в числовые поля можно
  ввести только цифры, а неподходящее значение (вне диапазона, буфер не кратный шагу
  устройства, путь к журналу с недопустимыми символами) сразу заменяется последним
  принятым. Звучит сигнал, у поля всплывает подсказка — что поле принимает и что
  возвращено. «Сохранить» проверяет все поля ещё раз и при замене оставляет окно
  открытым, чтобы было видно, что изменилось.
- Полный список опций — [CONFIG.md](CONFIG.md), пример со всеми ключами —
  [real.settings.example.json](real.settings.example.json).
- **Язык** задаётся `application.language`: `"auto"` (язык Windows: русский,
  украинский, белорусский → русский, остальные → английский), `"ru"`, `"en"`.
  Интерфейс, журнал и комментарии в файле настроек — целиком на одном языке.
  Окно настроек переходит на выбранный в нём язык сразу (введённое не теряется),
  остальная программа и комментарии в файле — после «Сохранить»; при ручной правке
  файла — при следующем запуске; значения сохраняются. Файл, у которого язык комментариев совпадает с
  текущим, не перезаписывается.
- Комментарии-справка стоят **в тех же строках**, что и значения: строку можно
  читать слева направо («параметр → значение → что это значит»).
- Служебные поля `configVersion` и `commentLanguage` идут без комментариев —
  менять их вручную не нужно.

### 1.6. Windows 11 и диагностика
Разбор механизма и рисков — в плане, §3.5. В коде:
- ошибки инициализации выводятся как **HRESULT с расшифровкой**
  (например, `AUDCLNT_E_UNSUPPORTED_FORMAT (0x88890008)`), а не как бессмысленный
  `GetLastError()`;
- обрабатывается `AUDCLNT_E_ENGINE_PERIODICITY_LOCKED`: если буфер движка уже задан
  другим приложением, REAL принимает его и держит поток с ним, так что малый буфер
  остаётся и после закрытия того приложения;
- отсутствие `IAudioClient3` (Bluetooth, часть виртуальных драйверов) даёт понятное
  сообщение вместо непонятной ошибки;
- в Windows 11 процесс REAL помечается для системы как экономный (EcoQoS): он
  только держит поток и ждёт событий, а звук обрабатывает служба Windows Audio,
  поэтому на звук это не влияет;
- манифест приложения объявляет поддержку Windows 10/11 (иначе система включает
  режим совместимости), включены long paths и масштабирование интерфейса
  **per-monitor v2**: окна и шрифты считаются от DPI того монитора, на котором
  окно находится, поэтому нестандартный масштаб (например, 225 %) больше не даёт
  мыльной картинки и обрезанных подписей;
- сборка — Release со статическим рантаймом (`/MT`), без зависимости от
  Visual C++ Redistributable;
- **отчёт `--diagnose`** («Диагностика → Диагностика» в окне): версия Windows,
  приложение, настройки, число логических ядер и ядра, которые Windows
  зарезервировала для звука (строка «Процессор»), активные устройства того
  направления, которое задано в `audio.dataFlow`, с именем драйвера, версией,
  форматом и поддерживаемыми размерами буфера (строка «буфер»: `стандартный`,
  `минимальный`, `базовый шаг`, `максимальный`) — по нему сразу видно, почему на
  конкретном устройстве малый буфер недоступен.
  **Базовый шаг — это не размер буфера, а ступень**, с которой движок меняет
  размер буфера: он свободно может быть меньше минимального (в отчёте встречается
  «базовый шаг 1 фрейм (0,01 мс)»), и запрашивать его вместо буфера нельзя — REAL
  никогда не просит буфер меньше минимального. Фиксированный буфер в настройках
  принимает значения от минимального до максимального, кратные шагу;
- **не держим поток зря**: если драйвер не умеет буфер меньше стандартного
  (Bluetooth, HDMI/DP, часть вендорских драйверов), приложение не создаёт поток
  вообще и сообщает об этом в статусе: «драйвер уже отдаёт минимальный буфер
  (10,00 мс) - <устройство>». Это убирает побочный эффект «занятого» ядра CPU;
- **повтор при временной недоступности endpoint'а**: если устройство в момент
  применения ещё не готово (`ERROR_NOT_FOUND`, `AUDCLNT_E_DEVICE_INVALIDATED`,
  остановка службы аудио), попытка повторяется с нарастающей паузой.

## 2. Как проверить за 5 минут

1. Скачать готовый `REAL.exe`: вкладка **Actions** → последний зелёный запуск
   *build* → блок **Artifacts** → `REAL-x64`. Положить в отдельную папку
   (портативно, ничего не устанавливается).
2. Запустить `REAL.exe`. В трее должен появиться значок; окно — со строкой
   состояния внизу вида `2,67 мс - Динамики (Realtek(R) Audio)` (она же дублируется
   первой строкой меню значка).
3. Проверить главное:
   - **«Свернуть»** → окно уходит в трей, программа продолжает работать (значок на
     месте, звук не «прыгает»); **крестик** по умолчанию завершает программу (с
     «Кнопка закрытия: Свернуть в трей» он тоже прячет окно в трей);
   - **левый клик** по значку — окно показывается/прячется;
   - **правый клик** → меню: строка состояния, «REAL запущен», «Перезапустить» —
     «Файл журнала», «Диагностика» — «Настройки» — «Выход» (строка состояния,
     «Настройки» и «Выход» есть всегда, остальные пункты можно скрыть в настройках;
     разделитель скрытой группы не рисуется);
   - **строка меню окна**: «REAL» («REAL запущен» с галочкой, «Перезапустить» —
     разделитель — «Выход»), «Опции» («Настройки», «Запускать с Windows» с
     галочкой), «Диагностика» («Диагностика» — тот же отчёт `REAL-diagnostics.txt`,
     «Открыть журнал» — `REAL.log`, если запись включена и файл существует) и
     «О программе»; внизу окна — **строка состояния**, в её правом конце — маленькая
     кнопка с круглой стрелкой («Перезапустить», подсказка при наведении);
   - **«Опции → Настройки»** (или «Настройки» в меню значка) → окно «Настройки REAL»
     с тремя вкладками (Окно / Звук / Прочее), вкладки рисует системный Tab-контрол:
     настройки собраны в группы в рамках: язык (переключатели «Как в Windows»,
     «English», «Русский» сразу за подписью «Язык:»), значок в трее и пункты его
     меню (под подписью «Пункты меню значка:», в два столбца), уведомления,
     устройства и буфер (под названием поля фиксированного буфера — диапазон
     устройства, только при «Фиксированном»), автоматический перезапуск,
     приоритет процесса REAL, проверка обновлений при запуске, журнал и файл
     настроек (путь — щелчок копирует путь к папке, «Открыть», «Перечитать» —
     заново читает файл в окно, если его правили вручную); у части настроек при наведении всплывает описание; внизу
     кнопки «Отмена» и «Сохранить» (пишет `real.settings.json`). Окна настроек и
     «О программе» открываются рядом с главным окном, а не в центре экрана;
   - **кнопка с круглой стрелкой** — аудиопотоки создаются заново, в окне появляется
     новая запись;
   - **пункт «О программе»** — своё окно: иконка приложения, крупное жирное имя,
     версия сборки (с номером CI и коммитом), фраза «Пока REAL запущен, Windows
     использует минимальный аудиобуфер, поддерживаемый драйвером устройства.» в две
     строки (окно шириной по самой длинной строке, поля слева и справа одинаковые),
     путь к файлу настроек (длинный путь сокращается посередине, имя
     файла видно всегда) и **кликабельные ссылки**: «Проект»
     (github.com/Mutaracha/REAL), затем «Инструкция» (docs/usage.ru.md) и
     «Параметры» (docs/CONFIG.md) — каждая открывается в браузере;
   - в папке с exe появился `real.settings.json`; `REAL.log` появляется, только если
     в настройках выбран уровень журнала (по умолчанию файл журнала выключен).
4. Сценарии, которые стоит проверить отдельно:
   - подключить/отключить наушники или USB-звук → в логе «Аудиоустройство
     изменилось, применяю заново», задержка применяется заново (автоматически). Если в момент
     события устройство ещё не готово (`HRESULT 0x80070490`), приложение
     повторит попытку само (2 с, 4 с, 8 с … до 30 с) и напишет об этом в лог;
   - переключить устройство по умолчанию в «Параметры → Звук» → то же самое;
   - «Спящий режим» → пробуждение, и блокировка → разблокировка (Win+L): в журнале
     «Выход из спящего режима, применяю заново» или «Разблокировка сеанса, применяю
     заново»;
   - закрыть `explorer.exe` и запустить снова (значок должен вернуться).
5. Если что-то не работает:
   - нажмите **«Диагностика» → «Диагностика»** в строке меню окна (или выполните
     `REAL.exe --diagnose`) —
     появится `REAL-diagnostics.txt` с версией Windows, списком устройств,
     драйверами и поддерживаемыми размерами буфера; блоки разделены строками вида
     `--- Устройства вывода (воспроизведение) ---`, а размеры буфера устройства
     перечислены по одному в строке (`стандартный 1920 фреймов (10,00 мс)`) —
     этот файл вместе с `REAL.log` достаточно приложить к вопросу;
   - журнал по умолчанию выключен: выберите «Прочее → Журнал → Уровень» —
     «Основное (info)» или, для подробного лога, «Подробно (debug)»
     (`logging.level`); уровень применяется сразу после «Сохранить» (или запустите
     программу с `--log-level debug` — только на этот запуск).

## 3. Полезные настройки (файл `real.settings.json`)

Все значения из этого раздела есть и в окне настроек — окно пишет тот же файл.
Ниже — то же самое текстом, для ручной правки и для версионирования.

Комментарии в файле бывают на том же языке, что интерфейс: служебное поле
`commentLanguage` помнит язык оформления, и после смены языка приложения файл
перезаписывается один раз — с новыми комментариями, значения не теряются. Если
язык не менялся, файл при запуске не перезаписывается. Второе служебное поле,
`configVersion` (текущее значение — `1`), помнит оформление файла: файл с другим
номером приложение один раз перезаписывает в текущем виде — значения, которые
программа знает, сохраняются, а ключи, которых в программе больше нет, из файла
исчезают. Незнакомый ключ не ломает запуск: о нём пишется предупреждение в журнал.

```jsonc
{
  // служебные поля
  "configVersion": 1,
  "commentLanguage": "ru",
  "application": {
    "minimizeToTray": true,           // «свернуть» → в трей
    "closeButtonAction": "exit",      // крестик: exit (выход) | minimize (в трей)
    "startMinimizedToTray": false,    // старт сразу в трее
    "startWithWindows": false         // автозапуск (HKCU\...\Run)
  },
  "tray": {
    "enabled": true,
    "notifications": { "onError": true, "onDeviceChange": true, "onStateChange": true },
    "menu": { "reinitialize": true, "diagnostics": true }
  },
  "audio": {
    // обрабатываются все устройства по умолчанию этого направления, включая
    // «устройство связи по умолчанию» (отдельной настройки роли нет)
    "dataFlow": "render",             // render | capture | both
    "buffer": "min",                  // min | fixed (размер - fixedBufferFrames)
    "reinit": {
      "defaultDeviceChanged": true,
      "deviceStateChanged": true,
      "deviceAdded": false,
      "deviceRemoved": false,
      "resumeFromSleep": true,
      "sessionUnlock": true,
      "debounceMs": 1000              // пауза перед перезапуском, мс (500–60000)
    }
  },
  "performance": {
    "processPriority": "normal"       // normal | belowNormal | idle (низкий); на звук не влияет
  },
  "updates": {
    "checkOnStartup": true            // одна проверка при запуске; false - ни одного запроса
  },
  "logging": {
    // только файл журнала: в окне программы всегда видны операции уровня info
    "level": "off",                   // off - файл не ведётся; иначе error | warn | info | debug | trace
    "filePath": "REAL.log",
    "maxFileSizeMb": 1,
    "maxFiles": 3
  }
}
```

## 4. Командная строка

| Команда | Что делает |
|---|---|
| `REAL.exe` | запуск с окном (и значком в трее, если он включён) |
| `--tray` / `--no-tray` | стартовать скрытым в трее / с окном |
| `--reinit` | перезапустить: заново создать аудиопотоки (команда передаётся работающей копии) |
| `--enable` / `--disable` | включить/выключить снижение задержки |
| `--exit` | закрыть работающую копию |
| `--config <путь>` / `--no-config` | другой файл настроек / без него |
| `--log-level <уровень>` | off, error, warn, info, debug, trace (другое слово — предупреждение, ключ не применяется) |
| `--diagnose` | отчёт о системе и аудиоустройствах в `REAL-diagnostics.txt` |
| `--help`, `--version` | справка / версия |

Полная справка по ключам — `REAL.exe --help`; справка по настройкам — комментарии
внутри `real.settings.json` и [CONFIG.md](CONFIG.md).

### 4.1. Какая сборка запущена
Версия везде — в `--version`, в справке, в окне «О программе», в отчёте
диагностики и в первой строке журнала — содержит номер сборки CI и коммит:
`REAL v0.3.0 RC <номер> (<коммит>)`: номер — это номер запуска сборки
в GitHub Actions, коммит в скобках — тот, из которого собран exe. Сборка,
сделанная вручную из репозитория, показывает только коммит, а сборка из архива
без репозитория — только номер версии.

## 5. Сборка

### 5.1. GitHub Actions (ничего устанавливать не нужно)
Пуш в ветку запускает `.github/workflows/build.yml`: сборка Release на
windows-2022, дымовой тест (запуск exe, вторая копия с `--exit`, проверка
`REAL.log`) и публикация `REAL.exe` в Artifacts. Пуш тега `v*` дополнительно
создаёт релиз и прикладывает exe.

### 5.2. Локально, MSVC без CMake
```bat
cd real-app
build.bat
```
`build.bat` сам находит установленный Visual Studio / Build Tools через `vswhere`
(подходит и «Build Tools 18» = VS 2026, toolset v145), компилирует ресурсы и
исходники и кладёт результат в `real-app\build\REAL.exe`. Нужен компонент
**C++ build tools** и Windows 11 SDK.

### 5.3. Локально, CMake
```bat
cd real-app
run-cmake.bat
```
Важно: генератор `Visual Studio 18 2026` требует **CMake 4.2+** (VS 2026
отвязывает версию MSVC от версии CMake). Если CMake старше — `run-cmake.bat`
переключится на «Visual Studio 17 2022» или используйте `build.bat`.

## 6. Ограничения, о которых стоит знать

- **Буфер нельзя уменьшить, если его уже задало другое приложение**:
  ядро отдаёт `AUDCLNT_E_ENGINE_PERIODICITY_LOCKED`. REAL в этом случае принимает
  текущий буфер (это видно в статусе: «(буфер задан другим приложением)»);
  собственный буфер REAL после закрытия того приложения возвращает «Перезапустить».
- **Bluetooth** — 10 мс по определению профиля; **HDMI/DisplayPort** — зависит от
  ресивера; **виртуальные драйверы** и часть вендорских (Realtek/ACX) малый буфер
  не поддерживают. Для встроенных кодеков обычно помогает переход на «High
  Definition Audio Device» (см. README).
- Действие низкой задержки **глобальное**: пока REAL работает, все приложения
  устройств по умолчанию работают с малым буфером, а это повышает риск треска при
  высокой нагрузке на CPU. Приоритет процесса REAL на это не влияет: звук
  обрабатывает служба Windows Audio.
- Пока поток с малым буфером активен, Windows может зарезервировать одно ядро
  процессора для звука: другие программы получают его в последнюю очередь, и в
  мониторинге оно выглядит недогруженным. Это особый режим низкой задержки самой
  Windows, а не утечка в REAL; есть ли такое ядро, показывает строка «Процессор»
  отчёта диагностики.
- Язык интерфейса — русский или английский (`application.language`), выбирается
  автоматически по языку Windows при первом запуске.
