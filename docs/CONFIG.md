# `real.settings.json` — справочник по настройкам

Файл лежит рядом с `REAL.exe` (создаётся при первом запуске). Формат — JSON,
поэтому лишняя запятая в конце списка не допускается, зато комментарии `//` и
`/* */` **разрешены** (перед разбором они вырезаются, строки в кавычках не
затрагиваются). Кодировка — UTF-8, BOM допускается. Файл, создаваемый приложением, содержит
комментарии-справку по каждому параметру (см. раздел «Справка в самом файле»).

Приоритет значений:

```
командная строка  >  <каталог exe>\real.settings.json  >  встроенные значения по умолчанию
```

Ключи командной строки (`--tray`, `--no-tray`, `--log-level`) действуют только
на текущий запуск: в файл они не записываются, а запись автозапуска следует за
файлом. Неизвестный уровень в `--log-level` не применяется, о нём пишется
предупреждение в журнал.

Если файл повреждён, приложение пишет причину в журнал (и один раз показывает
уведомление у значка) и работает на значениях по умолчанию, ничего не перезаписывая.
Если после этого сохранить настройки, прежний текст файла остаётся рядом —
`real.settings.json.bad`. Файл записывается через временный (`real.settings.json.tmp`
подменяет прежний целиком), поэтому прерванная запись не оставляет обрезанного
файла. Неизвестные ключи игнорируются с предупреждением в журнал — опечатка не
ломает запуск. Файл больше 1 МБ не читается совсем (это заведомо не файл настроек):
приложение называет причину и работает на значениях по умолчанию.

Неподходящее значение (не того типа, вне допустимого диапазона, неизвестное слово)
не применяется. Вместо него берётся последнее используемое значение: при запуске —
значение по умолчанию, при «Перечитать» в окне настроек — значение, которое уже
действует. Предупреждение в журнале называет ключ, причину и значение, которое
используется, например: «`audio.reinit.debounceMs`: значение 70000 вне диапазона
500–60000; используется 1000». Число, не помещающееся в диапазон целых, тоже
считается вне диапазона, а не обрезается до «подходящего».

Готовый пример со всеми ключами: [real.settings.example.json](real.settings.example.json)
(это тот же файл, который приложение создаёт при первом запуске, плюс шапка со ссылками).

Правки удобнее делать в **окне «Настройки REAL»**: его открывают пункт
**«Опции → Настройки»** строки меню окна программы и пункт **«Настройки»** меню значка
в трее. Окно пишет этот же файл тем же кодом, поэтому результат одинаков, а
неподходящее значение оно не примет. Разделы окна описаны ниже.

Строка меню главного окна: **«REAL»** («REAL запущен» — включение и выключение
снижения задержки, «Перезапустить», «Выход»), **«Опции»** («Настройки», «Запускать с
Windows» — тот же `application.startWithWindows`), **«Диагностика»** («Диагностика»,
«Открыть журнал») и **«О программе»**. Кнопка с круглой стрелкой в правом конце строки
состояния — тот же «Перезапустить» (подсказка при наведении).

## Справка в самом файле

При первом запуске создаётся `real.settings.json`, в котором рядом с каждым
параметром стоит комментарий с его назначением и допустимыми значениями — файл
является справочником сам по себе. Комментарий пишется **в той же строке**, что и
значение, поэтому значение и его пояснение читаются вместе. Комментарии удаляются при чтении
(строки в кавычках не затрагиваются), поэтому такой файл остаётся корректным JSON
для любых внешних инструментов после снятия комментариев.

Два служебных поля (`configVersion` и `commentLanguage`) идут в начале файла без
комментариев: у них нет значений на выбор, менять их вручную не нужно.

Дополнительно есть встроенная справка:

* `REAL.exe --help` — ключи командной строки;
* `REAL.exe --diagnose` — отчёт о системе, устройствах и поддерживаемых размерах буфера
  (`REAL-diagnostics.txt` рядом с exe, тот же отчёт пишет пункт
  **«Диагностика → Диагностика»** строки меню окна программы).

## Окно настроек

Пункт «Опции → Настройки» строки меню (или «Настройки» в меню значка) открывает окно
«Настройки REAL», которое правит тот же файл. Три вкладки рисует системный
Tab-контрол, поэтому они не могут наложиться друг на друга:

| Раздел | Что в нём |
|---|---|
| **Окно** | язык, автозапуск, старт свёрнутым, «свернуть в трей», поведение крестика, значок в трее и пункты его меню, уведомления |
| **Звук** | устройства (воспроизведение, запись или оба), буфер (минимальный или фиксированный) и размер фиксированного буфера, условия автоматического перезапуска, ожидание ответа устройства и пауза перед перезапуском |
| **Прочее** | приоритет процесса REAL, проверка обновлений при запуске, уровень журнала (он же включает и выключает файл), путь, размер и число файлов, файл настроек (путь к нему, «Открыть», «Перечитать») |

Окно выглядит как обычный диалог Windows: у программы включены визуальные стили
системы. Настройки каждой вкладки собраны в группы — рамки с полужирной подписью на
верхней линии («Приложение», «Значок в трее», «Уведомления» и т. д.); рамки одной
вкладки одной ширины. Размер окна подстраивается под содержимое: ширина — по самой
широкой строке, высота — по самой высокой вкладке (сейчас это «Окно»); оба
пересчитываются, когда окно переносят на монитор с другим масштабом.

У каждой группы своя колонка подписей: списки и поля группы стоят сразу за самой
длинной её подписью, а после подписи стоит двоеточие («Кнопка закрытия:»). Каждый
список не шире своего самого длинного значения на русском или английском, поэтому
смена языка ничего не сдвигает; числовое поле — по ширине своего наибольшего
значения, а поля группы «Журнал» — по ширине списка «Уровень». Все кнопки окна одного
размера: стандартная высота кнопки Windows и ширина по самой длинной подписи.

На вкладке «Окно» язык выбирается переключателями в одну строку сразу за подписью
«Язык:» — «Как в Windows», «English», «Русский» (стрелки меняют выбор, Tab переходит
дальше). Названия языков всегда написаны на самих этих языках и от языка окна не
зависят, переводится только «Как в Windows». В группе «Значок в трее» за флажком
«Показывать значок в трее» идёт подпись «Пункты меню значка:» и пункты его меню,
которые можно скрыть, в два столбца — как группы самого меню: «REAL запущен» и
«Перезапустить», рядом «Файл журнала» и «Диагностика». Пока значок выключен, подпись
и пункты серые, как и три флажка группы «Уведомления» ниже: уведомления показывает
значок. Строка состояния, «Настройки» и «Выход» есть в
меню всегда, флажков для них нет. Без значка серыми становятся и «Запускать свёрнутым
в трей», «Сворачивать в трей» и «Кнопка закрытия»: окну некуда прятаться, поэтому
кнопки окна работают как обычно — «Свернуть» сворачивает его на панель задач, крестик
завершает программу, а при запуске окно видно сразу.

На вкладке «Звук» список «Буфер» выбирает минимальный или фиксированный буфер. Поле
«Фиксированный буфер, фреймы» доступно только для фиксированного. Под названием поля
серым написан диапазон устройства по умолчанию, например «Допустимо: 144–480, шаг 48
(3,00–10,00 мс)»; при «Минимальном» эта подсказка скрыта, а её строка остаётся пустой,
чтобы ничего не сдвигалось. Если выбрать «Фиксированный» при пустом поле, в него
подставляется буфер, с которым устройство работает сейчас. Поле принимает только
значение из диапазона устройства, кратное шагу (см. «Проверка значений» ниже). Пока
устройство ни разу не запускалось и диапазон неизвестен, проверяется только, что это
целое число от 1 до 100000.

Если задержать указатель мыши на настройке или на её подписи, всплывает короткое
описание: что она делает. Описания есть у «Запускать с Windows», «Запускать свёрнутым
в трей», «Сворачивать в трей», «Кнопка закрытия», «Устройства», «Буфер»,
«Фиксированный буфер, фреймы», «Приоритет процесса», «Путь к файлу», «Размер файла,
МБ» и «Сколько файлов хранить»; они всплывают и тогда, когда настройка серая.

Уровень журнала выбирается из списка, где уровни идут от «ничего» к «всему»:
«Выключен (off)», «Ошибки (error)», «Предупреждения (warn)», «Основное (info)»,
«Подробно (debug)», «Всё (trace)». В скобках — значение, которое записывается в файл.

С клавиатуры: при открытии фокус стоит на вкладках (стрелки влево и вправо их
переключают), **Tab** проходит по полям открытой вкладки и только потом по кнопкам
внизу окна, **Ctrl+Tab** и **Ctrl+Shift+Tab** (а также **Ctrl+PgDn** и **Ctrl+PgUp**)
переключают вкладки из любого поля, **Esc** закрывает окно, как «Отмена».

Внизу окна две кнопки: **Отмена** (ничего не меняется) и **Сохранить** (записывает
файл, значения применяются сразу). Сам файл — на вкладке «Прочее», в группе «Файл
настроек»: путь к нему (длинный путь сокращается в середине, имя файла остаётся
видно) и кнопки **Открыть** (тот же файл в редакторе, для ручной правки) и
**Перечитать** (заново прочитать файл в окно: значения из файла заменяют то, что
показано сейчас, применяет их по-прежнему «Сохранить»). Если файл прочитать не
удалось, «Перечитать» называет причину — например, место лишней запятой.
Всё применяется сразу, перезапускать программу не нужно. Если в файле, прочитанном
кнопкой «Перечитать», есть неподходящие значения, они не заменяют показанные в окне,
а после чтения окно перечисляет их — с причиной и значением, которое оставлено.

### Проверка значений

В числовые поля можно ввести только цифры, и не больше, чем у наибольшего допустимого
значения. Когда фокус уходит из поля (Tab, щелчок по другому полю), значение
проверяется. Пустое значение, значение вне диапазона, буфер не кратный шагу устройства
или путь к журналу с символами `< > " | ? *` в поле не остаются: возвращается
последнее принятое значение этого поля (при открытии окна — действующее), звучит
системный сигнал, и у поля на несколько секунд всплывает подсказка — что поле
принимает и что возвращено, например «Допустимо: 500–60000. Возвращено: 1000.». Для
буфера подсказка называет диапазон и шаг устройства и ближайшие подходящие значения.

«Сохранить» проверяет все поля ещё раз. Неподходящее значение возвращается так же,
окно переключается на вкладку этого поля, показывает подсказку и остаётся открытым,
чтобы было видно, что изменилось; повторное «Сохранить» записывает файл. Серые поля
(фиксированный буфер при «Минимальном», файл журнала при уровне «Выключен») не
проверяются: их значения не используются. Пределы у окна и у чтения файла одни и те
же, поэтому значение, принятое окном, не отбрасывается при следующем запуске.

## Язык

Интерфейс, журнал и комментарии в `real.settings.json` бывают либо полностью
русскими, либо полностью английскими — смеси нет. Язык берётся из параметра
`application.language`:

* `"auto"` (по умолчанию) — язык системы: русский, украинский и белорусский
  дают русский интерфейс, любой другой — английский;
* `"en"`, `"ru"` — принудительно английский или русский (регистр не важен,
  понимаются и `"english"`, `"russian"`).

Другое значение — предупреждение в журнале и последнее используемое значение языка
(при запуске — `"auto"`).

Проверка языка выполняется до создания файла настроек, поэтому комментарии
пишутся сразу на нужном языке. Файл помнит язык своих комментариев в служебном
поле `commentLanguage`: если язык приложения изменился (например, в файле
поправили `application.language`), при следующем запуске файл перезаписывается —
комментарии становятся на новом языке, **значения при этом сохраняются**
(переписывается только оформление, прочитанные значения записываются обратно). Язык,
выбранный в окне настроек, переписывает комментарии сразу после «Сохранить».
Файл, в котором язык комментариев совпадает с текущим, **не перезаписывается**:
запуск ничего в нём не меняет, даже порядок строк и ваши собственные правки
оформления.

## `application`

| Ключ | Тип | По умолчанию | Описание |
|---|---|---|---|
| `language` | `"auto"` \| `"en"` \| `"ru"` | `"auto"` | язык интерфейса, журнала и комментариев в этом файле; `auto` — язык Windows (русский, украинский, белорусский → русский, остальные → английский). См. раздел «Язык» |
| `startMinimizedToTray` | bool | `false` | стартовать свёрнутым в трей (аналог `--tray`); без значка в трее окно стартует видимым |
| `minimizeToTray` | bool | `true` | «Свернуть» прячет окно в трей, а не в панель задач; без значка в трее — обычное сворачивание |
| `closeButtonAction` | `"minimize"` \| `"exit"` | `"exit"` | что делает крестик окна: свернуть в трей или завершить программу; без значка в трее крестик всегда завершает программу |
| `startWithWindows` | bool | `false` | автозапуск (запись `REAL` в `HKCU\...\CurrentVersion\Run`) |

Копия программы всегда одна: повторный запуск `REAL.exe` (в том числе с `--reinit`,
`--enable`, `--disable`, `--exit`) передаёт команду работающей копии и завершается, не
трогая ни файл настроек, ни журнал.

## `tray`

| Ключ | Тип | По умолчанию | Описание |
|---|---|---|---|
| `enabled` | bool | `true` | показывать значок в трее; подсказка всегда содержит состояние, например `REAL - 2,67 мс - Динамики` |
| `notifications.onError` | bool | `true` | уведомление об ошибках: одно на сбой, а не на каждую попытку |
| `notifications.onDeviceChange` | bool | `true` | уведомление о смене устройства |
| `notifications.onStateChange` | bool | `true` | уведомление о включении и выключении снижения задержки и о ручном «Перезапустить» |
| `menu.toggleEnabled` | bool | `true` | пункт «REAL запущен» — включение и выключение снижения задержки |
| `menu.reinitialize` | bool | `true` | пункт «Перезапустить» |
| `menu.openLog` | bool | `true` | пункт «Файл журнала» |
| `menu.diagnostics` | bool | `true` | пункт «Диагностика» — отчёт об устройствах |

Уведомления показываются, только когда окно программы скрыто (в трее) или свёрнуто:
пока окно открыто, то же самое видно в его журнале. При запуске программы и при
автоматических перезапусках (выход из сна, разблокировка сеанса, проверка потока)
уведомлений о включении нет; после выхода из сна и разблокировки нет и уведомления о
смене устройства — устройство не менялось.

Меню значка: строка состояния, «REAL запущен», «Перезапустить» — разделитель —
«Файл журнала», «Диагностика» — разделитель — «Настройки» — разделитель — «Выход».
Строка состояния, «Настройки» и «Выход» есть всегда. Разделитель, у которого скрыты
все пункты группы, не рисуется: двух линий подряд не бывает.

### Какие устройства обрабатываются

В Windows у каждого устройства есть **несколько «по умолчанию»**: обычное устройство
по умолчанию и устройство связи по умолчанию («Параметры → Система → Звук»; в
Windows 10 — «Параметры звука»). Технически это три роли — `console`, `multimedia`
и `communications`, причём первые две почти всегда указывают на одно и то же
устройство, а третья — на «устройство связи по умолчанию».

REAL сам берёт **все** устройства по умолчанию для выбранного `dataFlow`
(устройство по умолчанию и устройство связи по умолчанию) и держит малый буфер на
каждом из них — слышно и игру, и звонок. Совпадающие устройства (обычно `console` и
`multimedia`) обрабатываются один раз, так что лишних потоков не создаётся.

### Буфер: `buffer` и `fixedBufferFrames`

Буфер движка измеряется во фреймах: чем меньше фреймов, тем ниже задержка. Драйвер
устройства сообщает диапазон, в котором он готов работать, — его видно в отчёте
диагностики (строка «буфер»: `стандартный … минимальный … базовый шаг … максимальный …`)
и под полем фиксированного буфера в окне настроек. Базовый шаг — это **ступень**, с
которой меняется размер буфера: допустимы значения от минимального до максимального,
кратные шагу. Сам шаг размером буфера не является: он может быть меньше минимального
(например, 1 фрейм), и тогда ничего не разрешает — буфер всё равно не бывает меньше
минимального.

| Значение `buffer` | Что запрашивается |
|---|---|
| `"min"` | минимальный буфер устройства — самая низкая задержка, которую оно умеет |
| `"fixed"` | буфер из `fixedBufferFrames` фреймов |

Окно настроек принимает фиксированный буфер, только если он входит в диапазон
устройства по умолчанию и кратен шагу. Значение, которое устройство не принимает
(файл правили вручную, или устройство сменилось), программа подгоняет — округляет
вниз до шага и удерживает в диапазоне — и один раз пишет в журнал, например:
«Фиксированный буфер 500 фреймов не подходит устройству «Динамики» (144–480, шаг 48),
используется 480 фреймов.» `"fixed"` без размера (`fixedBufferFrames: 0`) при чтении
файла даёт предупреждение, и берётся минимальный буфер.

Если буфер движка уже задан другой программой (игрой или студийной программой,
которая сама просит малый буфер), Windows не даёт его менять, пока та работает. REAL
в этом случае берёт заданный буфер и держит поток с ним — в журнале строка
«Буфер аудиодвижка уже задан другим приложением, используется его размер: …».
Малый буфер сохраняется и после закрытия той программы; собственный буфер REAL
возвращает «Перезапустить» (пункт меню или круглая стрелка в строке состояния).

Дополнительно приложение раз в 30 секунд проверяет, что поток жив и что
устройство по умолчанию — то же самое; при расхождении потоки перезапускаются
автоматически.

Если применить снижение задержки не удалось (устройство выключено, служба звука
перезапускается), попытки повторяются с растущей паузой (2 с → 30 с), но не
дольше `reinit.failureTimeoutMs`. Уведомление показывается один раз — на
начало сбоя, а не на каждую попытку. Когда отведённое время прошло,
приложение больше не опрашивает устройство и выключает снижение задержки
(в строке состояния — «отключено: аудиоустройство не отвечает»); как только
приходит событие об устройстве, снижение задержки включается снова — так же, как
после выключения вручную.

Если устройства по умолчанию нет совсем (например, при старте вместе с Windows
звуковые устройства ещё не готовы), в журнале предупреждение «Аудиоустройство по
умолчанию не подключено.» — это не ошибка программы, а то, что мешает ей работать.
Как только устройство появляется, снижение задержки применяется само.

При запуске журнал называет параметры словами окна настроек: «Снижение задержки
применено для устройств воспроизведения; буфер минимальный.» (для обоих направлений и
фиксированного буфера — «…для устройств воспроизведения и записи; буфер
фиксированный, 480 фреймов.»). Дальше каждое применение — одна строка-итог на языке
интерфейса: «Снижение задержки активно: <устройство>, 48000 Гц, 2 канала, 32 бит,
буфер 336 фреймов (7,00 мс)» — либо «Драйвер уже отдаёт минимальный буфер…», если
снижать нечего. Перезапуск после сна или разблокировки начинается строкой «Выход из
спящего режима, применяю заново» или «Разблокировка сеанса, применяю заново».
Имя устройства не переводится. Подробная строка о каждом потоке («Поток с низкой
задержкой запущен…») пишется только на уровне `debug` — для разбора проблем.

## `performance`

| Ключ | Тип | По умолчанию | Описание |
|---|---|---|---|
| `processPriority` | `"normal"` \| `"belowNormal"` \| `"idle"` | `"normal"` | приоритет процесса как в диспетчере задач: обычный, ниже среднего, низкий |

Раздел относится к самому процессу REAL и на звук не влияет: звук обрабатывает служба
Windows Audio, а процесс REAL только держит поток и ждёт событий. По той же причине
в Windows 11 процесс REAL всегда помечается для системы как экономный (EcoQoS:
пониженная частота, энергоэффективные ядра) — без настройки и без строк в журнале.

## `updates`

| Ключ | Тип | По умолчанию | Описание |
|---|---|---|---|
| `checkOnStartup` | bool | `true` | одна проверка при запуске; `false` — ни одного сетевого запроса за всю сессию |

Релизы читаются из репозитория проекта (`Mutaracha/REAL`), он вшит в сборку и
настройкой не меняется.

Обновления никогда не проверяются **во время работы** приложения: нет ни пункта меню,
ни периодических запросов. Единственная возможная проверка — одна при старте, и
только если `checkOnStartup: true`. Найденная версия лишь
показывается уведомлением со ссылкой на страницу релиза; скачивания, установки и
принудительного закрытия нет. Таймаут запроса зашит в приложение (15 секунд).

Проверка — один запрос к странице `https://github.com/Mutaracha/REAL/releases/latest`.
GitHub перенаправляет его на страницу последнего релиза, и версия берётся из адреса
этой страницы (`…/releases/tag/v0.3.1`); у этого способа нет лимита API (60 запросов
в час на один адрес), поэтому общий IP (VPN, провайдер) ему не мешает. Если релизов
ещё нет, GitHub отправляет на список релизов — в журнале строка «Опубликованных
версий пока нет.», уведомления нет: это обычный ответ, а не ошибка. Ошибка (нет сети,
GitHub отклонил запрос) пишется в журнал и, если включено
`tray.notifications.onError`, показывается уведомлением.

## `logging`

Раздел описывает **только файл журнала**. Окно программы от него не зависит: оно
всегда показывает основные операции и ошибки на уровне `info`. По умолчанию файл
не ведётся (`off`); чтобы разобрать проблему, выберите уровень `info` или подробнее.

| Ключ | Тип | По умолчанию | Описание |
|---|---|---|---|
| `level` | string | `"off"` | `off` — файл не ведётся совсем; `error`, `warn`, `info`, `debug`, `trace` — от самого краткого **файла** к самому подробному (в окне настроек — от «Выключен (off)» до «Всё (trace)»); понимаются и `none`, `warning`, `err`, другое слово — предупреждение в журнале |
| `filePath` | string | `"REAL.log"` | путь относительно каталога exe или абсолютный; окно настроек не примет пустой путь и символы `< > " \| ? *` |
| `maxFileSizeMb` | int | `1` | размер одного файла, МБ (1–1024): дальше начинается следующий |
| `maxFiles` | int | `3` | сколько файлов хранить (1–100) |

Каждая строка журнала начинается с даты, времени и уровня: `[2026-10-01 12:00:00.000] [info] …`,
`[error]`, `[warning]`. Файл — это запись о том, что делала программа; подсказки
для пользователя (например, почему журнал сейчас нельзя открыть) попадают только в
окно.

## `configVersion`

Служебное поле (текущее значение — `1`). Номер оформления файла: он меняется, когда
меняется сам файл, а приложение сверяет его со своим. Файл с другим номером
приложение один раз перезаписывает в текущем оформлении: значения, которые программа
знает, сохраняются, а ключи, которых в программе нет, из файла исчезают. Вручную
править не нужно.

Ключи, которых программа не знает, не ломают запуск: при чтении они пропускаются с
предупреждением в журнал («`application.example`: неизвестный параметр,
игнорируется») и исчезают при следующей записи файла.

## `commentLanguage`

Служебное поле: язык комментариев в этом файле (`"en"` или `"ru"`, у нового файла —
язык, на котором он создан). Приложение сравнивает его с текущим языком и при
расхождении перезаписывает файл с комментариями на новом языке, сохраняя все
значения. Вручную править не нужно.
