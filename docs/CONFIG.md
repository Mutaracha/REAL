# `real.settings.json` — справочник по настройкам

Файл лежит рядом с `REAL.exe` (создаётся при первом запуске). Формат — JSON,
поэтому лишняя запятая в конце списка не допускается, зато комментарии `//` и
`/* */` **разрешены** (перед разбором они вырезаются, строки в кавычках не
затрагиваются). Кодировка — UTF-8, BOM допускается. Файл, создаваемый приложением, содержит
комментарии-справку по каждому параметру (см. раздел «Справка в самом файле»).

Приоритет значений:

```
командная строка  >  <каталог exe>\real.settings.json  >  встроенные значения по умолчанию
```

Если файл повреждён, приложение пишет об этом в журнал и работает на значениях
по умолчанию, ничего не перезаписывая. Неизвестные ключи игнорируются с
предупреждением в журнал — опечатка не ломает запуск.

Готовый пример со всеми ключами: [real.settings.example.json](real.settings.example.json)
(это тот же файл, который приложение создаёт при первом запуске, плюс шапка со ссылками).

Правки удобнее делать в **окне «Настройки…»** (строка меню окна программы или пункт
«Настройки» меню значка): окно пишет этот же файл тем же кодом, поэтому результат
одинаков, а опечатку в числе оно не примет. Разделы окна описаны ниже.

---

## Справка в самом файле

При первом запуске создаётся `real.settings.json`, в котором рядом с каждым
параметром стоит комментарий с его назначением и допустимыми значениями — файл
является справочником сам по себе. Комментарий пишется **в той же строке**, что и
значение, поэтому значение и его пояснение читаются вместе. Комментарии удаляются при чтении
(строки в кавычках не затрагиваются), поэтому такой файл остаётся корректным JSON
для любых внешних инструментов после снятия комментариев.

Два служебных поля (`configVersion` и `commentLanguage`) идут в начале файла без
комментариев: у них нет значений на выбор, менять их вручную не нужно.

Дополнительно есть встроенная справка:

* `REAL.exe --help` — ключи командной строки;
* `REAL.exe --diagnose` — отчёт о системе, устройствах и поддерживаемых периодах
  (`REAL-diagnostics.txt` рядом с exe, тот же отчёт пишет пункт **Diagnostics**
  меню **Файл** в окне программы).

## Окно настроек

Пункт «Настройки…» строки меню открывает окно, которое правит тот же файл:

| Раздел | Что в нём |
|---|---|
| **Окно** | язык, автозапуск, старт свёрнутым, «свернуть в трей», поведение крестика, консоль, одна копия, значок в трее, уведомления, состав меню значка |
| **Звук** | включение при запуске, потоки, роль устройства, период, размер буфера, автоподбор периода, освобождение устройств, условия повторной активации и её таймауты |
| **Прочее** | приоритет процесса, энергосбережение, горячие клавиши, проверка обновлений, уровень журнала, файл журнала, размер и число файлов |

Кнопки: **Сохранить** (записывает файл; значения применяются сразу), **Отмена**
(ничего не меняется) и **Открыть файл** — тот же файл в редакторе, для ручной правки.
`showConsole` и `tray.enabled` вступают в силу при следующем запуске — окно об этом
напоминает. Значения вне допустимого диапазона (например, размер файла журнала 0)
окно не применяет и показывает, какое поле проверить.

## Оформление окон

Окна программы оформлены системно: тот же шрифт, цвета и элементы, что и в
остальных программах Windows. Своего тёмного варианта у REAL нет: меню, полосы
прокрутки, флажки и кнопки рисует сама Windows, и надёжно перекрасить их в тёмный
цвет можно только недокументированными средствами — из-за этого тема из версии 3
убрана целиком. Ключ `application.theme` из файла версии 3 читается без
предупреждений и не используется.

## Язык

Интерфейс, журнал и комментарии в `real.settings.json` бывают либо полностью
русскими, либо полностью английскими — смеси нет. Язык берётся из параметра
`application.language`:

* `"auto"` (по умолчанию) — язык системы: русский, украинский и белорусский
  дают русский интерфейс, любой другой — английский;
* `"en"`, `"ru"` — принудительно английский или русский (регистр не важен,
  понимаются и `"english"`, `"russian"`).

Проверка языка выполняется до создания файла настроек, поэтому комментарии
пишутся сразу на нужном языке. Файл помнит язык своих комментариев в служебном
поле `commentLanguage`: если язык приложения изменился (например, в файле
поправили `application.language`), при следующем запуске файл перезаписывается —
комментарии становятся на новом языке, **значения при этом сохраняются**
(переписывается только оформление, прочитанные значения записываются обратно).
Файл, в котором язык комментариев совпадает с текущим, **не перезаписывается**:
запуск ничего в нём не меняет, даже порядок строк и ваши собственные правки
оформления.

## `audio`

| Ключ | Тип | По умолчанию | Описание |
|---|---|---|---|
| `enabledOnStartup` | bool | `true` | включать снижение задержки сразу при запуске |
| `dataFlow` | `"render"` \| `"capture"` \| `"both"` | `"render"` | какие устройства обрабатывать (воспроизведение/запись/оба) |
| `role` | `"console"` \| `"multimedia"` \| `"communications"` | `"console"` | роль устройства по умолчанию |
| `periodSelection` | `"min"` \| `"fundamental"` \| `"fixed"` | `"min"` | какой период запрашивать |
| `requestedPeriodFrames` | int | `0` | период для `"fixed"` (кадров); приводится к кратному `fundamental` и обрезается по `[min, max]` |
| `allowPeriodSnap` | bool | `true` | если период уже зафиксирован другим приложением — принять текущий, а не падать с ошибкой |
| `releaseOnExit` | bool | `true` | освобождать поток при выходе (аудиодвижок возвращается к 10 мс сам) |
| `reinit.defaultDeviceChanged` | bool | `true` | переинициализация при смене устройства по умолчанию |
| `reinit.deviceStateChanged` | bool | `true` | при переходе устройства в активное/неактивное состояние |
| `reinit.deviceAdded` | bool | `true` | при появлении нового устройства |
| `reinit.deviceRemoved` | bool | `false` | при удалении устройства |
| `reinit.resumeFromSleep` | bool | `true` | после выхода из сна/Modern Standby |
| `reinit.sessionUnlock` | bool | `true` | после разблокировки сеанса |
| `reinit.debounceMs` | int | `1000` | антидребезг: Windows присылает пачку событий подряд |
| `reinit.enableWhenDisabled` | bool | `true` | при подключении устройства или смене устройства по умолчанию включать снижение задержки, даже если оно было выключено |
| `reinit.failureTimeoutMs` | int | `60000` | сколько миллисекунд ждать ответа устройства (5000–3600000); по истечении режим выключается, а опрос устройства прекращается |

Дополнительно приложение раз в 30 секунд проверяет, что поток жив и что
устройство по умолчанию — то же самое; при расхождении активация выполняется
автоматически.

Если применить режим не удалось (устройство выключено, служба звука
перезапускается), попытки повторяются с растущей паузой (2 с → 30 с), но не
дольше `reinit.failureTimeoutMs`. Уведомление показывается один раз — на
начало сбоя, а не на каждую попытку. Когда отведённое время прошло,
приложение больше не опрашивает устройство и выключает снижение задержки
(в строке состояния — «отключено: аудиоустройство не отвечает»); как только
приходит событие об устройстве, режим включается снова, если разрешено
`reinit.enableWhenDisabled`.

В строке журнала остаётся один итог применения: «Снижение задержки активно:
<устройство>, 48000 Hz, 2 ch, 32 bit, period 336 frames (7.00 ms)» — либо
«Драйвер уже отдаёт минимальный буфер…», если снижать нечего. Отдельные строки
«Применяю режим…» и «Поток с низкой задержкой запущен…» убраны: первая была
шумом, вторая теперь пишется только на уровне `debug` (для разбора проблем).

## `updates`

| Ключ | Тип | По умолчанию | Описание |
|---|---|---|---|
| `mode` | `"off"` \| `"manual"` | `"off"` | `off` — ни одного сетевого запроса за всю сессию; `manual` — единственная проверка при запуске (см. ниже) |
| `checkOnStartup` | bool | `false` | выполнить один запрос при запуске (работает только при `mode = "manual"`) |

Релизы читаются из репозитория проекта (`Mutaracha/REAL`), он вшит в сборку и
настройкой не меняется. Ключ `repository` из старых файлов принимается и
игнорируется.

Обновления никогда не проверяются **во время работы** приложения: нет ни пункта меню,
ни периодических запросов. Единственная возможная проверка — одна при старте, и
только если `mode: "manual"` и `checkOnStartup: true`. Найденная версия лишь
показывается уведомлением со ссылкой на страницу релиза; скачивания, установки и
принудительного закрытия нет. Таймаут запроса зашит в приложение (15 секунд).

## `hotkeys`

| Ключ | Тип | По умолчанию | Описание |
|---|---|---|---|
| `enabled` | bool | `true` | регистрировать глобальные горячие клавиши |
| `toggleEnabled` | string | `"Ctrl+Alt+L"` | включить/выключить снижение задержки |

Поддерживаются модификаторы `Ctrl`, `Alt`, `Shift`, `Win` и клавиши `A`–`Z`,

попадёт предупреждение, приложение продолжит работать.

## `logging`

| Ключ | Тип | По умолчанию | Описание |
|---|---|---|---|
Раздел описывает **только файл журнала**. Консоль настраивается отдельно: она
появляется при `application.showConsole` или ключе `--console` и всегда показывает
основные операции и ошибки на уровне `info`, независимо от этих параметров.

| Ключ | Тип | По умолчанию | Описание |
|---|---|---|---|
| `level` | string | `"info"` | `trace`, `debug`, `info`, `warn`, `error`, `off` — подробность **файла** |
| `toFile` | bool | `true` | писать файл журнала |
| `filePath` | string | `"REAL.log"` | путь относительно каталога exe или абсолютный |
| `maxFileSizeMb` | int | `1` | размер файла до ротации |
| `maxFiles` | int | `3` | сколько файлов хранить |

Каждая строка журнала начинается с даты, времени и уровня: `[2026-10-01 12:00:00.000] [info] …`,
`[error]`, `[warning]`. Файл — это запись о том, что делала программа; подсказки
для пользователя (например, напоминание о горячих клавишах) попадают только в
окно и в консоль. Ключ `toConsole` из старых файлов принимается и игнорируется.

## `configVersion`

Служебное поле (текущее значение — `4`). Номер версии оформления файла: во второй
версии комментарий стоит в одной строке со значением, в третьей был параметр
`application.theme`, в четвёртой он убран (оформление окон — системное). Файл со
старым номером приложение один раз перезаписывает в текущем оформлении — все
значения при этом сохраняются, а ключ `theme` из файла версии 3 исчезает. Вручную
править не нужно.

## `commentLanguage`

Служебное поле: язык комментариев в этом файле (`"en"` или `"ru"`, у нового файла —
язык, на котором он создан). Приложение сравнивает его с текущим языком и при
расхождении перезаписывает файл с комментариями на новом языке, сохраняя все
значения. Вручную править не нужно.
